# Nginx 离线升级

从已连接服务器的「工具包」双击「Nginx 升级」。HTTPS 证书工具也提供「检查 / 升级 Nginx 的 SSL 支持」入口，可带入当前程序、主配置路径和 sudo 选择。

1. 填写 **Nginx 程序完整路径**（含程序名）、**主配置文件**和**本机健康检查地址**。例如 `/usr/local/nginx/sbin/nginx`、`/usr/local/nginx/conf/nginx.conf`、`http://127.0.0.1:8800/`。
2. 点击「检测兼容性」，核对系统架构、运行库、当前版本、模块、master、启动方式和 HTTP 检查结果。普通用户管理 root 实例时，需要启用已经配置好的免密 sudo。
3. 检查通过后，核对服务器与升级方式，勾选确认并点击「备份并升级」。工具上传内置包、校验摘要、用新版检查现有配置，然后切换程序。全程显示当前阶段和日志。
4. 成功后点击「继续配置 HTTPS 证书」。升级只增加程序能力，不自动开放端口、生成证书或修改站点。

## 运行方式

- 独立启动的 Nginx 使用官方 USR2 平滑换代：启动新版 master，旧 worker 停止接收新连接，通过连续健康检查后退出旧 master。已有连接可继续收尾。
- 由 systemd 管理的实例通过对应服务重启，**会短暂中断**；检测结果中提前明确显示。复杂的服务前后置脚本需要人工维护。
- 保留当前认证用户、权限和主配置，不重新登录其他账户。sudo 使用非交互方式，不保存或请求 sudo 密码。
- 当前使用第三方模块、动态模块、多个 master 共用程序、复杂启动指令、无法确认的默认路径时，阻止自动升级并说明原因。

## 麒麟 V10

按实际 CPU 架构和运行库选择包，不把所有“麒麟 V10”视为相同环境。目标为常见 Linux x86_64 与 aarch64（ARM64），glibc 2.28 及以上。桌面版与服务器版的发行说明、内核及安全策略可能不同。

不会关闭 SELinux、KYSEC 或其他系统安全策略。候选程序执行或配置检查被系统阻止时，停止升级，由管理员按本单位要求处理。没有麒麟实机验证的构建不等于已经通过麒麟厂商认证。

## 备份和失败处理

备份位于程序同级的 `.elushell-nginx-<任务编号>` 目录，仅当前执行账户可访问，包含原程序 `original`、已加载配置的副本 `configuration`、恢复说明 `README.txt` 和完成后的 `exit-code`。其中可能包含配置中的敏感信息，应按服务器文件管理要求保管。

切换失败时尝试恢复原程序并检查服务。无法确认恢复成功时显示「请核对服务器运行状态」，保留升级锁，避免重复操作；不要仅根据桌面断开连接认定升级失败或成功。先核实进程、响应和备份，再由管理员处理。

配置检查通过仅表示语法和依赖可用，健康检查仅验证所填接口。业务涉及其他端口、域名、上游和长连接时，升级后仍应做对应业务检查。

## 构建维护

源码和编译依赖采用固定版本、摘要校验，构建脚本位于 `scripts/build-nginx-bundle.sh`、`scripts/build-nginx-arm64.sh`。构建始终在非 root 隔离目录完成，不能对业务目录执行安装。最终包和许可证随 EluShell 分发，升级时不要求目标服务器联网、安装编译器、Python 或 Java。

内置程序需要随安全更新持续维护。跨架构模拟器测试与麒麟物理服务器实测应分别记录，不互相替代。
