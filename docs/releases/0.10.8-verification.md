# 0.10.8 — Drag files to server directories

Remote rows now initiate a server-bound move of the selected visible entries. Tree rows are complete drop targets, with destination highlighting, delayed expansion and edge scrolling. A modal captures the server, destination and item list at drop time; confirmation starts the operation, cancellation does not change files. External native files are distinguished from remote items and retain their native paths through confirmation. Tree blank space is rejected; right-hand folder rows accept uploads into that folder, while the list background targets its current directory.

The SFTP move checks every entry before starting: root, same-directory, self/descendant (including directory aliases), nested selections and destination name conflicts are rejected. Standard non-overwriting SFTP RENAME is used, with no shell interpolation, copy/delete fallback or implicit overwrite. Runtime failures are reported per source; successful moves and failed sources remain explicit. Refresh retains tree expansion and does not switch to another session. Upload overwrite/merge behavior remains unchanged.

Validation reports are in `test-results/file-drop-*.json`, `test-results/release-0108-summary.json`, and the full unit suite output. macOS preview packages use the shared implementation and offline archive/signature checks; actual Mac runtime and Gatekeeper testing remain unavailable.
