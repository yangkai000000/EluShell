# 0.10.9 — File batch actions and session menus

Delete confirmation now uses the application dialog with server identity, wrapped paths, selected-item count and a cancel-first focus. The same flow covers single items and multi-selection. Permission editing applies one mode to the selected paths; recursion remains explicit. SFTP batch operations validate root paths and modes before mutation, deduplicate overlapping recursive selections, continue after per-item errors, and return successful and failed paths. Recursive partial failures are explicitly described in the dialog.

Session context actions distinguish disconnect from close. Reconnection replaces the session at its existing tab position and rebinds dependent tool tabs without switching an unrelated active tab. Connect-all targets only open disconnected sessions, prompts for missing credentials and can skip an entry. Explicit disconnect closes SSH; editor text remains available but cannot be saved through the disconnected connection. Closing a tab retains the existing editor connection lifetime behavior. Close-left/right/others/all use the context target, protect tool dependencies, preserve active deployments/certificates/Nginx operations, and prompt before stopping captures. Backend task guards remain authoritative.

Upload confirmation now dismisses immediately before starting background upload. The right-hand transfer panel owns progress/cancellation. A test blocks SFTP writes while verifying the modal has closed and the file list is interactive.

Validation: full unit suite 37 files / 160 tests; final Windows package tests recorded in context-actions-packaged.json, files-packaged.json, file-drop-packaged.json and terminal-files-packaged.json. Isolated loopback SSH/SFTP fixtures were used, not business servers. Both Mac preview archives and ad-hoc signature/resource hashes were checked offline; no Mac runtime or Gatekeeper testing was available. Release and guide checks are recorded in release-0109-summary.json.
