# SSH 连接工具调研与 EluShell 能力扩展建议

调研日期：2026-09-11。对照基线：EluShell 0.8.2 的 README、配置模型、SSH 实现、终端组件和 AI 使用说明。

## 结论

建议继续定位为面向开发者的 SSH 运维工作台，下一阶段依次解决「复杂环境连接」「多服务器并行操作」「文件传输可靠性」。现有监控、文件编辑、命令库和 AI 已形成基础，优先把这些能力串成日常排障流程。

本次选择 FinalShell、Xshell、MobaXterm、SecureCRT、Termius、PuTTY 六款常见、有长期产品积累的工具作为样本。没有取得可比的活跃用户数据，因此不提供市场占有率或使用量排名。竞品能力依据官方网页和文档，未逐款安装实测；部分功能受版本、平台或付费套餐限制。下文优先级是结合本项目现状的产品判断，不是厂商结论。

## 2. 我们已经有的能力

以下能力应作为增强基础，避免重新列成待开发功能：

- SSH 多标签、密码/私钥/Agent 认证、主机指纹验证；已经设置 15 秒 keepalive 和最多 3 次未响应检测。
- 连接文件夹、标签、搜索、最近连接和自有格式导入导出。
- 本地与远程端口转发；暂时只有 local/remote 两种规则。
- SFTP 文件及目录上传下载、多选批量下载、任务进度与取消、权限修改、远程文本编辑及保存冲突检查。
- CPU、内存、磁盘、网络和进程监控；进程筛选与终止。
- 共享命令库、命令历史、多行草稿，以及向当前或全部已连接会话发送命令。
- 终端输出搜索、字体和背景配置、面板尺寸持久化。
- AI 流式聊天、自定义兼容接口、对话历史、命令填入及人工点击执行。

依据：[README](../README.md)、[连接与配置类型](../src/shared.ts)、[SSH 服务](../electron/ssh.ts)、[AI 说明](AI-ASSISTANT.md)。本次为静态核对，没有重新执行产品测试。README 的部分历史边界仍标注 0.8.1，版本基线以 package.json 的 0.8.2 为准。

## 3. 能力扩展清单

P0：优先解决连接阻碍和凭据迁移问题。P1：提升高频工作效率与可靠性。P2：建立差异化或团队能力，需求确认后推进。工作量为相对判断，不是工期承诺。

| 优先级 | 能力 | 当前差距 | 建议首版范围 | 价值 / 相对工作量 |
| --- | --- | --- | --- | --- |
| P0 | 跳板机与代理 | 未提供配置与连接链路 | 单跳 SSH 网关、HTTP CONNECT/SOCKS5 上游代理；终端、SFTP、监控共享同一通道策略；预留多跳模型 | 能连接企业内网环境 / 大 |
| P0 | 交互式认证与通用终端 | 仅 password/key/agent；启动命令依赖 `/bin/sh` | keyboard-interactive 多轮提示以支持服务器要求的 OTP/MFA；增加通用 SSH shell 模式；Linux 监控探测失败时仍可使用终端 | 扩大服务器与设备覆盖 / 中到大 |
| P0 | 凭据安全迁移 | 本机密码已加密，但导出默认包含明文密码 | 保留不含密码的配置导出；增加独立口令保护的加密导出和恢复；清楚区分配置与凭据 | 换机、备份与分享更可靠 / 中 |
| P1 | 连接恢复和诊断 | 有 keepalive、断线状态和重连入口，缺少完整恢复策略 | 可配置重试退避/次数、取消重试、休眠唤醒提示；区分 DNS/TCP/认证/指纹/隧道失败 | 网络变化后少重复操作 / 中 |
| P1 | 分屏与项目工作区 | 多标签和面板尺寸已存在，未见多终端分屏及会话集合恢复 | 左右/上下分屏，保存连接集合、标签顺序、布局和目录书签；恢复前展示需要重连的主机 | 同时看日志和执行操作 / 大 |
| P1 | 更精确的多会话操作 | 目标只有当前/全部 | 勾选目标会话、按组选择、显示环境与目标数量、生产会话醒目标识；独立汇总发送成功和失败 | 降低批量操作选错目标的概率 / 中 |
| P1 | 传输恢复与队列 | 有进度/取消，未支持断点续传 | 暂停/继续、失败项重试、并发上限；持久化任务元数据；单文件续传先行，再扩展目录 | 大文件或不稳定网络下减少重传 / 大 |
| P1 | 参数化命令 | 已有静态命令库和历史 | `${service}`、`${path}` 等参数表单、必填/默认值、展开预览、环境变量复用；之后再做多步骤模板 | 将常用命令变成可复用操作 / 中 |
| P1 | 日志留存和输出阅读 | 有搜索和 6000 行内存回滚，没有完整输出日志能力 | 手动开启会话日志、时间标记、轮转/保留设置、关键词高亮、选区导出 | 排障复盘与共享结果 / 中 |
| P1 | 隧道管理增强 | 已有 -L/-R，但随会话生命周期，修改需要重连 | 独立列表、单条启停与状态、端口冲突定位，后续增加 -D 动态 SOCKS | 访问数据库、内网 Web 更方便 / 中 |
| P1 | 迁移已有主机 | 支持自有格式，尚未见外部工具导入 | 优先 OpenSSH config 和 CSV，提供映射预览、去重与不支持字段报告；再按用户来源增加 PuTTY/Xshell | 降低切换成本 / 中 |
| P2 | 文件效率与兼容性 | UTF-8 小文本编辑、递归 SFTP 已有基础 | 目录比较预览、打包传输、编码选择、外部编辑器；按堡垒机使用反馈决定 rz/sz | 覆盖更多文件操作 / 中到大 |
| P2 | 排障上下文与 AI | AI 当前不自动读取终端和文件 | 用户选择日志/指标后预览并附加；输出解释、排查步骤、命令草稿；执行后可选带回结果 | 让已有 AI 帮助实际排障 / 中 |
| P2 | 运维信息联动 | 指标与进程详情已有，但需用户手动关联 | 进程→监听端口→服务目录→日志路径联动；容器列表与日志入口；最近异常指标快照 | 提升现有监控价值 / 中 |
| P2 | 团队共享与跨设备同步 | 当前以本地配置和导入导出为主 | 先个人加密备份/恢复，再团队项目共享、成员权限和变更历史 | 有团队需求后再投入 / 大 |
| P2 | 本地终端与其他协议 | 当前主要覆盖 Linux SSH | 本地 PowerShell/WSL 优先候选；RDP、串口、X11 根据目标用户选择 | 扩大适用场景 / 大 |

## 4. 最值得先做的三个交付包

### A. 企业网络连接包

范围：单跳 SSH、上游代理、keyboard-interactive、连接阶段诊断；同步补齐加密导出。先打通一条可靠链路，再做多跳和认证资料批量复用。

验收要点：

- 目标主机无法直连但可通过跳板到达时，终端、SFTP、监控均能工作。
- 每一跳独立验证主机指纹；认证失败指出具体节点；中途取消释放连接。
- 服务器多轮挑战能正确展示、按 echo 标记处理输入；取消登录不保存 OTP。
- 代理失败、目标端口拒绝和 SSH 密钥失败能区分原因，不把所有错误显示成超时。
- 加密导出跨设备可恢复，错误口令或文件被修改时拒绝导入；继续支持仅配置导出。

### B. 多服务器工作区包

范围：分屏、工作区保存/恢复、选定会话发送、参数化命令。

验收要点：

- 同时展示日志会话和操作会话，输入焦点及目标主机始终明确。
- 关闭重开后可恢复布局与连接配置引用；凭据不写入布局数据。
- 从 10 个会话中选择 3 个发送，只影响这 3 个；断开的会话单独报告失败。
- 参数替换后先展示最终命令；参数作为数据插入时正确处理空格和引号。
- 分屏不能将「只有一个活动会话」简单变成所有会话高频监控，应对可见面板设置总采样预算。

### C. 文件与排障可靠性包

范围：单文件续传、失败队列重试、会话日志与关键词高亮；随后增加显式选择上下文的 AI 分析。

验收要点：

- 中断上传/下载后可继续，完成后与原文件校验一致。
- 续传前验证源文件身份；源文件已改变时停止续传，提示重新开始。
- 应用重启保留任务元数据；部分文件成功、部分失败时只重试需要的项目。
- 日志能够受控启停和轮转，长时间大输出不会无限占用内存或磁盘。
- AI 请求仅包含预览确认的上下文，排障建议先成为可编辑命令草稿。

## 5. 实现时需要保留的边界

1. **重新连接不等于恢复远程进程。** 自动重连只能重建 SSH 通道。若要继续原交互任务，应提供可选 tmux 集成并检测服务器是否支持；现有目录同步也需要单独适配。不要自动重放上次命令或有副作用的登录命令。
2. **通用终端与 Linux 增强模式分离。** 现有 `loginShellCommand()` 使用 `/bin/sh` 和登录 shell，监控依赖 `/proc`。网络设备或 Windows SSH 服务应走标准 shell 请求，按能力关闭不适用面板。终端可连接与监控可用需要分别判定。
3. **发送成功不代表命令执行成功。** 当前写入终端只确认发送。批量任务若要汇总退出码与耗时，需使用独立 exec 通道或明确的 Shell 集成；不能从任意 PTY 输出猜测结果。
4. **上游代理与动态转发是不同能力。** 前者帮助客户端连上 SSH 服务，后者让其他应用经 SSH 通道访问内网；配置和状态需要区分。
5. **日志不等于不可篡改审计。** 本地日志用于排障。命令行和服务器输出可能包含秘密，不能承诺自动识别全部密码；团队审计另需权限和服务端设计。PuTTY 官方也明确说明其敏感数据识别存在限制。[日志说明](https://www.chiark.greenend.org.uk/~sgtatham/putty/privacy.html)
6. **优先定义扩展接口，暂缓任意插件执行。** 可以为连接通道、认证、文件任务、监控采集、命令操作预留接口；插件市场和任意第三方代码加载的成本明显更高，待稳定需求出现后再设计。

## 6. 排期建议与验证方式

近期顺序建议为：连接包 → 多服务器工作区包 → 文件与排障可靠性包。每包拆分发布，避免把跳板机、自动重连、传输续传一次性耦合改造。

如果首批用户只管理可直连的少量 Linux 主机，可将工作区包提前；如果主要经堡垒机登录，应先核对是否允许 SSH 转发和 SFTP，不能假设支持跳板机就能兼容所有堡垒机流程。

正式承诺排期前，用代表性用户的真实流程验证三个问题：连接失败是否主要来自代理/认证；是否经常同时操作多台服务器；传输中断和命令复用是否形成持续痛点。同步记录任务完成时间、连接失败阶段、传输恢复成功率和工作区使用情况；指标采集方式需单独设计，本报告不表示已有遥测。

RDP/VNC/X11、完整团队云服务、任意插件市场和无人值守 AI 运维暂缓进入近期主线。macOS 真机验收与发行签名属于发布质量工作，应与功能扩展并行安排；现有测试包不能作为跨平台已验收的证据。
